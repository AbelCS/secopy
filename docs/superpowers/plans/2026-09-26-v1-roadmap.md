# Secopy v1 Roadmap

v1 is the scope of [RFD 0001](../../rfd/0001-secopy.md). It is split into four plans, one per
subsystem. Each plan produces working, tested software and ends in a release, which
release-please cuts from the Conventional Commits.

| # | Plan | RFD milestone | Release | Status |
|---|---|---|---|---|
| 1 | [Engine core](2026-09-26-engine-core.md) | M0 | 0.1.0 | Done (benchmarks on real hardware pending) |
| 2 | Engine complete | M1 | 0.2.0 | Not written |
| 3 | Desktop app | M2 | 0.3.0 | Not written |
| 4 | Packaging and release | M3 | 0.4.0 | Not written |
| — | Beta with real users and media | M4 | 0.5.x betas → **1.0.0** (`Release-As: 1.0.0`) | — |

Each later plan is written when the previous one is done, so it can build on what the
code and the benchmarks actually showed.

## 1. Engine core (M0)

The `secopy-core` library and the `secopy-cli` developer tool:

- scan (hidden skip, symlinks, extension stats, folder-vs-contents)
- copy with inline xxHash64 and atomic `.secopy-partial` → rename
- verify from the device with OS cache bypass, re-copy once on mismatch
- copy/verify lanes, progress events, cancel
- the `xxhsum`-compatible checksum file
- CI on all three OSes
- benchmarks against `cp` / `rsync` / `robocopy` on real hardware

Covers FR-1..14 (engine side), FR-18, FR-20, FR-21, FR-23..33 and FR-17a.

## 2. Engine complete (M1)

- **Pre-flight (FR-16):** destination writable, free space, destination inside the source,
  FAT32 4 GiB limit, invalid or reserved names for the destination file system, and
  case-sensitivity detection (which can relax FR-17a on case-sensitive destinations).
- **Conflicts (FR-17):** Skip (same size and mtime) / Overwrite / Keep both, replacing
  plan 1's "never overwrite".
- **Metadata (FR-19):** mtime, creation time, POSIX permission bits, directory mtimes.
- **Pause / resume (FR-22).**
- **Fatal-error detection:** destination disconnected, source volume gone, in addition to disk full.
- **Job report (FR-35):** text and JSON.
- **Performance work from the M0 benchmark findings:** preallocation, sequential-access
  hints, Windows small-file flushing, lane and buffer tuning, and an OS fast path for
  plain Copy with the checksum file off.
- **Fault-injection tests:** source removed mid-copy, destination unplugged, disk full.
- **Keep the machine awake** during a job.

### Carried over from plan 1 (final review and execution)

These must be handled in plan 2:

- **Stale partial files.** A `.secopy-partial` left by a crashed job now makes that file
  fail with `NameClash`, because partial files are created with `create_new`. Plan 2
  needs a cleanup policy, e.g. removing leftover partials during pre-flight.
- **Windows small-file speed is unmeasured.** Commits use a hard link there (NTFS), and
  `FlushFileBuffers` runs per file.
- **FAT/exFAT commit race.** Those file systems have no hard links and no no-replace
  rename, so the commit falls back to check-then-rename. Two jobs writing the same name
  into the same exFAT folder have a race window of microseconds.
- **Non-UTF-8 names** become U+FFFD in the checksum file, and can trigger a false
  `NameClash`, because the clash key is lossy. Compare raw bytes, and flag names the
  checksum file can't represent.
- **Scan path resolution.** `scan` uses `fs::canonicalize`: a symlinked source folder takes
  its target's name in FolderItself mode, and canonicalize fails on some Windows volumes
  (RAM disks, VeraCrypt, some network drives). Use `std::path::absolute`.
- **Memory for mid-size files.** Files between 4 and 8 MiB take the pipelined path inside
  the 8 small-file lanes, which can use about 128 MiB of buffers at once. Align
  `small_file_threshold` with the buffer size, or share the buffers.
- **Long names.** The 16-byte partial suffix makes 240–255-byte names fail with "file name
  too long".
- **Empty folders after a cancel.** All directories are created up front, so a cancel or a
  failure leaves empty folders for files that were never copied (FR-10).
- **CI gaps.** Clippy runs on Ubuntu only, so macOS/Windows `cfg` code isn't linted. Release
  PRs are created with `GITHUB_TOKEN`, so they don't trigger CI; use a PAT if that matters.
- **Unverified macOS cache bypass.** Check whether `F_NOCACHE` writes from unaligned
  buffers leave the file's last page in the cache, so the verify read of that page comes
  from RAM (FR-26). Needs a spike.
- **`bench.ps1` hasn't been run yet** on Windows.

## 3. Desktop app (M2)

Tauri 2 shell and a Svelte + TypeScript UI on top of `job::run_job`:

- the main window (RFD §5.2): pickers, drag and drop, extension chips, result-path preview,
  pre-flight messages
- the progress view (§5.3): overview bars, active-file rows, a virtualized finished list,
  smoothed speeds and ETAs
- the summary view (§5.4) and the settings page (§5.5)
- the dark design tokens (§5.6), notifications, keyboard shortcuts (FR-37), remembered
  state (FR-36), accessibility (NFR-10)

## 4. Packaging and release (M3)

- macOS universal binary, signed and notarized `.dmg`
- Windows signed installer plus a portable `.exe`
- Linux AppImage and `.deb`
- a release workflow that builds and attaches artifacts when a release-please tag is created
- the auto-updater, off by default (NFR-9)

## After v1 (RFD §11)

v1.1 for media offload: multiple destinations and ASC MHL. Later: include hidden files,
a light theme, paranoid verify, XXH3/XXH128, resume, "verify existing copy", a public CLI.
