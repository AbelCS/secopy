# Secopy v1 Roadmap

v1 is the scope of [RFD 0001](../../rfd/0001-secopy.md). It is split into five plans, one per
subsystem. Each plan produces working, tested software and ends in a release, which
release-please cuts from the Conventional Commits. Plans 1 and 2 share the first release,
0.1.0 (RFD §14, 2026-09-27).

| # | Plan | RFD milestone | Release | Status |

| 1 | [Engine core](2026-09-26-engine-core.md) | M0 | 0.1.0 | Done (real-hardware benchmarks moved to plan 4) |
| 2 | [Engine complete](2026-09-27-engine-complete.md) | M1 | 0.1.0 | Done ([design](../specs/2026-09-27-engine-complete-design.md)) |

Each later plan is written when the previous one is done, so it can build on what the
code actually showed.

Performance comes after the desktop app (RFD §14, 2026-09-26): tuning is internal to the
engine and doesn't change the API the app uses, so it is done once every operation and
setting works end to end. Correctness is not deferred: fault injection and the cache-bypass
check stay in plan 2.

## 1. Engine core (M0)

The `secopy-core` library and the `secopy-cli` developer tool:

- scan (hidden skip, symlinks, extension stats, folder-vs-contents)
- copy with inline xxHash64 and atomic `.secopy-partial` → rename
- verify from the device with OS cache bypass, re-copy once on mismatch
- copy/verify lanes, progress events, cancel
- the `xxhsum`-compatible checksum file
- CI on all three OSes
- benchmark scripts (the real-hardware runs moved to plan 4)

Covers FR-1..14 (engine side), FR-18, FR-20, FR-21, FR-23..33 and FR-17a.

## 2. Engine complete (M1)

Design: [2026-09-27-engine-complete-design.md](../specs/2026-09-27-engine-complete-design.md).

- **Pre-flight (FR-16):** destination writable, free space, destination inside the source,
  FAT32 4 GiB limit, invalid or reserved names for the destination file system, and
  case-sensitivity detection (which can relax FR-17a on case-sensitive destinations).
- **Conflicts (FR-17):** identical files are skipped; for files that differ, Keep both /
  Overwrite / Skip, replacing plan 1's "never overwrite".
- **Metadata (FR-19):** mtime, creation time, POSIX permission bits, directory mtimes.
- **Pause / resume (FR-22).**
- **Fatal-error detection:** destination disconnected, source volume gone, in addition to disk full.
- **Job report (FR-35):** text and JSON.
- **Fault-injection tests:** source removed mid-copy, destination unplugged, disk full.
- **Keep the machine awake** during a job.

### Carried over from plan 1 (final review and execution)

All handled in plan 2 (see its design, "Plan 1 carry-overs"). Windows small-file speed and
`bench.ps1` moved to plan 4. Using a PAT so release PRs trigger CI is still open (the
user's call).

## 3. Desktop app (M2)

Split in two (RFD §14): **3a** is a working app, designed in
[2026-09-27-macos-app-core-design.md](../specs/2026-09-27-macos-app-core-design.md): the main window,
Finder drag and drop, the non-empty destination warning, pre-flight and conflict choice,
progress at two updates a second, the summary, and an unsigned `.dmg` in each release.
**3b** is split in two (RFD §14, 2026-09-27). **3b-1**, designed in
[2026-09-27-profiles-settings-design.md](../specs/2026-09-27-profiles-settings-design.md):
the drives list, source profiles (FR-38), the Settings page, remembered state and recent
destinations, and the new app identifier. **3b-2**: notifications, Eject, keyboard
shortcuts and the accessibility pass.

The full list for the app:

A macOS app (RFD §14, 2026-09-27): Tauri 2 shell and a Svelte + TypeScript UI on top of
`job::run_job`, designed and tested on macOS (WKWebView):

- the main window (RFD §5.2): pickers, drag and drop, extension chips, result-path preview,
  pre-flight messages
- the progress view (§5.3): overview bars, active-file rows, a virtualized finished list,
  smoothed speeds and ETAs
- the summary view (§5.4) and the settings page (§5.5)
- the dark design tokens (§5.6), notifications, keyboard shortcuts (FR-37), remembered
  state (FR-36), accessibility (NFR-10)

## 4. Performance (M3)

Measure on real Macs, then tune until NFR-1..NFR-4 pass:

- run `scripts/bench.sh --purge` for SSD → SSD, card reader → SSD and SSD → external
  drive; record the findings against NFR-1..NFR-3 in `docs/benchmarks/`
- tuning driven by those findings: preallocation, sequential-access hints, lane and
  buffer sizes, and an OS fast path for plain Copy with the checksum file off
- memory at 1M files (NFR-4) and UI responsiveness under load (NFR-5)
- benchmarks in CI that fail on regressions (RFD §9)

## 5. Packaging and release (M4)

- Apple Silicon (`aarch64-apple-darwin`) build, signed and notarized `.dmg`
- a release workflow that builds and attaches artifacts when a release-please tag is created
  (in place since 0.1.0 for the CLI binary, `release-build.yml`; the app's `.dmg` joins it)
- the auto-updater, off by default (NFR-9)

## After v1 (RFD §11)

v1.1 for media offload: multiple destinations and ASC MHL. Windows and Linux apps (the
engine already builds and passes its tests there; `bench.ps1` and Windows small-file speed
move with them). Later: include hidden files,
a light theme, paranoid verify, XXH3/XXH128, resume, "verify existing copy", a public CLI.
